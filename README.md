# ようかん手帖 v4

iPhone Safariの縦画面を優先した、羊羹の実食・ストック・ウィッシュリスト管理PWA。

## 使い方

1. 右上の「＋ 記録」から商品名・お店・商品URL・写真などを登録。
2. 「食べた・評価する」を選ぶと味の記録フォームへ進む（途中で閉じると未評価品はストックに残る）。
3. 商品詳細の「＋ もう一度食べた」で、2回目以降を追加。各回の日付・量・ペアリング・点数・感想は別々に残る。
4. 「これからの羊羹」で「食べたいリスト」→「ストック」→「手帖」と移動可能。
5. 商品詳細で、今回の個人評価と全商品の平均を6軸レーダーチャートで比較。公式情報と実食レビュー傾向は採点をせず別枠で表示。
6. 「使い方」→「JSONバックアップを書き出す」で定期的に保存。旧v1/v2 JSONもインポート可能。

## フォント・色
- タイトル `Hina Mincho`、本文 `Kiwi Maru`。外部フォントが使えない場合は端末搭載フォントにフォールバック。
- 生成り＋くすみブラウン、アイコン背景はねこやなぎ色寄りの薄い灰緑。

## 公開
- `index.html`, `app.js`, `styles.css`, `sw.js`, `manifest.webmanifest`, `icon-180.png`, `icon-512.png` を同じディレクトリで公開。
- GitHub Pages等のHTTPS配信推奨。公開URLをSafariで開き「共有」→「ホーム画面に追加」。
- **旧アプリと同じURL・パスで置き換える場合**、同じIndexedDBが読み込まれる（ブラウザ内データを削除しないこと）。
- **別URLへ移す場合**は旧版でJSONバックアップを書き出し、新版の「使い方」からインポートする。
- キャッシュが古い場合はSafariで再読み込み。

## 評価データとプライバシー
- 個人記録はローカルのIndexedDB保存。写真は縮小後に端末ブラウザに保存。
- 公式情報・レビュー傾向は外部サイトへアプリが自動アクセスしない。コピーしたプロンプトをChatGPTへユーザー自身が送り、返却JSONを貼り付ける方式。
- ブラウザデータの消去やiOSのストレージ管理で消失し得るため、バックアップ必須。

## v4で追加した使い方

1. 商品編集で製法・素材・食感を設定し、必要なら本煉／小倉／小城羊羹を仕立てに記録します。
2. 詳細のレーダーチャートから比較平均を切り替えます。
3. 「好み」タブのランキングから総合／種類別を切り替えます。
4. 変わり種などは商品編集の「好みの分析に含める」をオフにできます。全商品平均やランキングからは消えません。
5. 従来v1〜v3バックアップをそのままインポートし、v4として新規バックアップ可能です。

## テスト
`tests/TEST_RESULTS_V4.md` に検証結果を記録。ローカルに Playwright と Chromium がある場合は `python tests/test_v4.py` で主要フローを再検証できます。


## v5 修正（2026-10-25）
- 確定・保存後に、商品詳細の上部および個人評価のグラフ横から「最新の評価を編集」できる。実食履歴の各回も「この回を編集」から編集できる。
- 編集時は同じセッションIDを上書き保存するため、実食回数は増えない。
- iPhone Safariの入力時自動ズーム対策として入力欄・選択欄・テキストエリアを16px以上に統一。キーボード表示時のダイアログ高さ・スクロールも補正。ユーザーによるピンチズームは維持。
- データ保存形式・DB・旧バックアップ互換はv4から変更していない。


## v5.1（2026-10-25）— iPhone Safari 日本語入力スクロール不具合修正

- v5で追加した `visualViewport.height` を使って編集中のダイアログを縮小する処理を削除。
- 商品情報・実食記録の入力画面をネイティブのモーダル `showModal()` から、通常文書内で表示する `show()` 方式に変更。
- フォーム内の独立スクロール・固定位置・固定高さを撤廃し、ページ全体を自然にスクロール。
- 入力欄の16px以上の文字サイズを維持。iPhone Safariでの手動ピンチズームは禁止しない。
- 既存のIndexedDB名、オブジェクトストア、レコード形式、バックアップv4互換、分類・評価・ランキングは変更なし。
- WebKit/iOS 26のキーボードと固定配置の競合を避けるための構造変更。Safari実機の最終確認は別途必要。


## v5.2 改修 (2026-10-25)
- コピー成功時はボタンが「✓ コピー完了！」に切り替わり、文章で永続的に確認できます。Safariなどで自動コピーに失敗した場合は手動コピー用テキストを表示します。
- 公開情報の参考評価JSONは、通常JSON・Markdownコードフェンス・説明文付きJSON・全角の組版引用符（“ ”）・末尾カンマに対応します。JSONとして解釈できない場合は入力文章を残したまま理由を表示します。
- 画面切り替えは短いフェード。アクセシビリティ設定「視差効果を減らす」に対応します。
- 商品／実食編集画面は余白タップで閉じません。明示的に「閉じる」を押し、入力内容が変わっていれば破棄前に確認します。
- 既存のDB、保存形式、エクスポート形式（schemaVersion:4）、旧版読み込みには変更ありません。

【注意】コピー・日本語キーボードはiPhone Safari実機での最終確認が必要です。


## v5.3 修正（2026-10-25）— 調査結果を文章へ変更
- 外部情報についての1〜10段階推定値を廃止。個人評価・過去の自己平均のレーダーチャートのみ使用。
- 「公式情報」「レビュー傾向」を別々の文章と出典として保存・表示。投稿日・調査日・レビュー数や情報の限界を記載可能。
- 調査依頼テンプレートから点数欄を削除。新スキーマは `generalEvaluation.officialInfo`, `reviewTrends`, `sources[]`, `confidence`, `assessedAt`（JSON内の `schemaVersion:2`）。
- 旧 `schemaVersion:1` JSONの混合メモも取り込み可能。`【公式一次情報】` と `【公開レビュー】` 等の見出しで明示された範囲は分けて表示し、不明瞭な範囲は「旧形式の調査メモ」として保持します。
- 特殊引用符・コードフェンス・説明文・余分な末尾カンマに加えて、`"sources": {...}, {...}` の配列括弧漏れを補修します。すべての誤記を修復できるわけではありません。
- 旧スコアは新画面に表示せず、従来DBの内容は残します。旧形式JSONを再取り込みした場合にも `legacyScores` として参考用に保持します（採点表示には不使用）。
- **アプリ全体の記録バックアップ書式は v4 を維持**。新しい外部調査メモの `schemaVersion:2` と区別してください。
- IndexedDBデータベース名・ストア名・バージョンを維持。ユーザーの実食データ・写真・ランキング・分類は変更しません。
- 更新前には必ず旧版からJSONバックアップを保存し、同じ公開URL/パスで上書きします。
